## 1. What did users actually try?

List observed commands, journeys, environments, and artifacts used. Separate completed behavior from stated intent.

## 2. What broke or confused them?

Record reproducible failures, time-to-recovery, misunderstood language, and evidence that was hard to locate.

## 3. What did users repeatedly ask for?

Include counts and context. Distinguish recurring jobs from suggested implementations.

## 4. Which assumptions got stronger or weaker?

| Assumption ID | Direction                     | Evidence | Confidence          |

|               | stronger / weaker / unchanged |          | high / medium / low |

## 5. What evidence supports the next priority?

Name the user behavior, defect frequency, safety issue, or experiment threshold that justifies the priority.

## 6. What will deliberately not be built this week?

List tempting features that lack evidence, exceed the wedge, or add risk before a validated need.

## 7. Should the project continue, narrow, pivot, or stop?

Choose one and compare the evidence with `03-validation-plan.md` thresholds.
