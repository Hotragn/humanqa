# Conventional and 10x module challenges

“10x” means a materially better user outcome, not ten times more features. Each alternative is bounded by a smallest test and an explicit release decision.

| Module               | Conventional implementation                      | 10x alternative                                                                                                                                     | User value                                                                                       | Technical cost | Smallest testable version                                                       | Failure mode                                                   | Timing                              |
| -------------------- | ------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ | -------------- | ------------------------------------------------------------------------------- | -------------------------------------------------------------- | ----------------------------------- |
| Journey execution    | Run a Playwright script and return pass or fail. | Produce a versioned evidence bundle with intent, safe-action policy, action timeline, and reproducible state.                                       | One failure can be understood by engineering, PM, and accessibility reviewers.                   | Medium         | One YAML journey, trace, screenshots, route list, and action log.               | The bundle is larger but not more useful than a trace.         | v0.1                                |
| Deterministic checks | Emit isolated lint-like warnings.                | Tie each rule result to the journey step, target metadata, raw evidence, uncertainty, and regression candidacy.                                     | Findings become explainable and reusable.                                                        | Medium         | Network, console, label/name, overflow, broken navigation, and assertion rules. | Noisy heuristics dilute trusted failures.                      | v0.1 with conservative rules        |
| Accessibility        | Run axe and list violations.                     | Reproduce the keyboard path where the declared goal becomes unreachable, alongside raw axe rule IDs and manual-test boundaries.                     | Teams can debug and regress a critical interaction instead of reading a compliance-looking list. | Medium-high    | Expected reachable selector plus bounded tab traversal and focus evidence.      | Valid focus containment is mislabeled as a trap.               | v0.1 advisory; deeper Keypath later |
| Product intent       | Store acceptance criteria as report prose.       | Version Quality Contracts that map each criterion to explicit evidence or a visible human-review state and later gate releases.                     | Ambiguity is exposed rather than hidden behind a green test.                                     | Medium         | Explicit criterion-to-assertion mapping in YAML.                                | Users duplicate tests or assume prose is executable.           | v0.1 schema; semantic mapping later |
| Reporting            | Write JSON and a terminal summary.               | Generate one portable decision artifact with executive verdict, raw evidence links, formulas, limitations, acceptance matrix, and next safe action. | Technical evidence becomes usable in release conversations.                                      | Medium         | JSON, Markdown, and static HTML from one normalized schema.                     | Presentation makes uncertain scores appear objective.          | v0.1                                |
| Scoring              | Count findings by severity.                      | Show transparent priority and risk contribution per finding, threshold reasons, confidence, and override context.                                   | Reviewers can reconstruct and challenge the decision.                                            | Low-medium     | Fixed severity weights and declared contract thresholds.                        | Teams cargo-cult a universal score.                            | v0.1 with disclaimers               |
| Test generation      | Paste reproduction steps into a code template.   | Gate generation on evidence sufficiency, prioritize semantic locators, preserve the finding ID, omit risky actions, and mark review points.         | The scaffold is safer and more maintainable.                                                     | Medium         | Generate one spec for an unlabeled control or failed expected navigation.       | Scaffold repair costs more than manual authoring.              | v0.1                                |
| Packs                | Commit static personas and sample YAML.          | Build versioned, attributed, fixture-tested packs that domain contributors can add without core changes.                                            | Domain expertise can enter the project through low-risk contributions.                           | Medium-high    | Zod schema, CLI validation, seven personas, eight journeys, and fixture tests.  | Generic journeys are brittle across applications.              | v0.1 foundation; registry later     |
| Agent skills         | Publish prompts that ask an agent to review UX.  | Constrain skills to HumanQA artifacts, evidence provenance, safety boundaries, output schemas, and human-review triggers.                           | Agent output is portable and less likely to invent observations.                                 | Low-medium     | Five self-contained `SKILL.md` packages with references, schemas, and examples. | Skills look credible but cannot execute without a working CLI. | v0.1 after engine                   |
| GitHub               | Post the entire report in a pull request.        | Format only release-relevant changes, annotations, evidence links, and next safe actions; keep mutations dry-run.                                   | Reviewers get signal without comment spam.                                                       | Medium         | Local dry-run Markdown formatter and example workflow.                          | Comments are too long or artifacts leak private data.          | v0.1 dry-run; API integration later |
| Privacy              | Add a warning to documentation.                  | Make local-first, redaction, screenshot opt-out, offline mode, consent metadata, and zero hidden telemetry inspectable in outputs.                  | Trust is an observable product behavior.                                                         | Medium         | Text redaction tests and privacy settings in every report.                      | Screenshot or domain-specific PII survives.                    | v0.1, with explicit limitations     |
| Visual evidence      | Save numbered screenshots.                       | Align screenshots, actions, requests, focus states, and findings on a navigable evidence timeline.                                                  | Non-engineers can follow causality.                                                              | High           | Link step screenshots from a static report.                                     | Viewer work delays reliable collection.                        | Later                               |
| Release portfolio    | Aggregate test statuses.                         | Let teams reconstruct a release decision across contracts, owners, thresholds, and confidence with every contribution linked to evidence.           | Release meetings become traceable.                                                               | High           | One-contract verdict in v0.1.                                                   | Dashboard implies precision before inputs are trusted.         | Later                               |

## Scope decision

The v0.1 “10x” move is the complete evidence-to-test chain, not autonomous intelligence. Visual timelines, semantic PRD parsing, managed registries, automatic pull requests, and team dashboards remain postponed until users validate the underlying evidence artifact.
